# anta-agent 架构设计

> 对应实现:`packages/anta-agent`。本文说明系统如何组织、每个设计决策为什么这样定。展示用途,面向技术评审。
>
> harness 分层参考 DeepSeek Harness 的插件化内核哲学与 Claude Code 的智能体工具链形态。

---

## 1. 总体结构:微内核 harness

anta-agent 采用微内核架构:**内核只拥有会话循环、事件总线与能力注册表,其余一切皆插件**——模型适配器、编程工具、命令、技能,乃至记忆引擎本身,都是以插件形态注册进来的能力。没有"只能改核心"的特权路径。

```
  内核(会话循环 + 事件总线 + 注册表)
    ├─ 模型适配插件:Anthropic / OpenAI / Google / Bedrock / llama.cpp(本地)
    ├─ 编程工具插件:read / bash / edit / write / grep / find / ls
    ├─ 记忆工具插件:memory_search / conversation_search
    ├─ 上下文管理:会话树、自动压缩、中文成本统计行
    └─ 记忆插件(核心差异):四层记忆引擎
```

代码布局(`packages/anta-agent/src/`):

```
  cli.ts                    # `at` 启动器:装配内核并加载内置插件
  anta-agent-extension.ts   # 记忆插件:经事件接缝接入会话生命周期,注册命令与工具
  host-adapter.ts           # 会话身份(稳定 sessionId,路径只作本地转录键)
  index.ts                  # SDK 导出(AntaAgent 门面)
  core/
    anta-agent-core.ts      # AntaAgent:宿主中立门面(capture/recall/search,永不抛错)
    config.ts               # 配置解析与默认值(全部集中此处)
    security.ts             # 不可信文本净化、注入检测
    l0/recorder.ts          # L0:JSONL 事实源 + SQLite 投影 + 回放恢复
    l1/extractor.ts         # L1 提取:场景分段 + 记忆候选
    l1/dedup.ts             # L1 去重:四决策(store/update/merge/skip)
    l1/writer.ts            # L1 写入:执行决策 + 审计
    scene/                  # L2:场景块抽取与索引
    persona/                # L3:人格生成与备份
    pipeline/manager.ts     # 调度器:触发时机、断点、串行锁
    recall/recall-context.ts# 召回注入格式(动态块/稳定块)
    store/                  # SQLite、FTS5、向量索引、RRF 融合、embedding 客户端
```

两层职责分离:

- **插件层**(anta-agent-extension.ts)跑在宿主运行时里:监听生命周期事件、改写消息、注册命令工具。TUI/RPC/脚本/SDK 所有模式都加载它。
- **引擎层**(core/)不依赖任何宿主:只依赖一个 `LlmRunner` 回调(单次文本补全)。这是宿主中立的接缝——换宿主或接远程后端,引擎层零改动。

## 2. 数据模型:四层记忆

| 层 | 内容 | 存储 | 生命周期 |
|---|---|---|---|
| L0 | user/assistant 消息全文 | 按天 JSONL + SQLite/FTS 投影 | 默认保留 30 天 |
| L1 | 原子记忆,7 类型(chat:persona/episodic/instruction;code:work_fact/work_task/work_method/work_artifact),priority 0–100(-1 为全局强指令) | SQLite | 长期,带版本号与合并历史 |
| L2 | 场景叙述块 | `scene_blocks/*.md` + 索引 JSON | 长期,每次合并前留备份 |
| L3 | 人格/工作画像 | `persona.md` | 长期,滚动备份 3 份 |

失败/中止的轮次不进 L0(错误或中止的 assistant 消息跳过)——半截回答不是事实。

## 3. 事实源与投影(L0)

**问题**:SQLite 是检索必需(FTS5、向量),但进程随时可能被杀,数据库也可能损坏。

**方案**:按天 JSONL 是事实源,SQLite 只是可重建投影。写序固定:**先写 JSONL,再写投影**——崩溃最坏留下"日志有、投影无"的行,绝不会有"投影有、日志无"的孤儿。启动时回放 JSONL 修复投影;确定性消息 id(sessionKey+role+timestamp+content 的 SHA1)让回放与重复捕获天然幂等(INSERT OR IGNORE)。

单行上限 1M 字符、sessionKey 上限 8K、内容上限 200K——畸形历史行跳过,不阻断后续行恢复。

## 4. 蒸馏管道(L0→L1→L2→L3)

### 触发时机

- **L1**:每 N 轮对话(默认 5;冷启动 warmup 1→2→4,首轮对话就产生记忆)或空闲 600 秒;关机时强制 flush。
- **L2**:L1 完成后延迟 10 秒调度;最小间隔 900 秒节流,积压超 3600 秒强制执行。
- **L3**:自上次生成后累计 50 条新记忆触发。

### 有界与不丢

单轮 L1 最多处理 400 条消息 / 120K 字符,超限分块,**每轮最多处理 3 块**,其余留待下轮;游标只推进已处理块——积压再大也不丢消息、不超时爆 prompt。水位线(checkpoint)原子写入(tmp+rename),重启从断点续跑。

### 去重:四决策

每条提取候选与现有记忆池对比,LLM 裁决四种动作:**store**(新建)/ **update**(更新既有)/ **merge**(合并多条,保留各方时间戳)/ **skip**(丢弃)。记忆库越用越准而非越用越肿。写入带追加式审计;主写不完整(部分失败或审计失败)整轮报错,不静默吞。

### 失败语义

管道、捕获、召回、检索**全部不向宿主抛错**——记忆是增强,不是依赖;任何记忆故障只降级(记日志),不阻塞对话。

## 5. 召回与注入

### 混合检索

两路并行:FTS5 BM25 关键词 + 向量余弦(embedding 开启时),**倒数排名融合(RRF,k=60)**合并——不需要两路分数可比,只看排名。中文英文单次检索全覆盖。相似度阈值 0.3,默认注入前 5 条;embedding 调用失败自动降级纯关键词,瞬时故障打不掉召回。召回整体 5 秒超时,超时静默跳过。

### 注入的缓存设计(关键决策)

- **动态内容**(本轮召回的记忆)以 `<relevant-memories>` 块前置到用户消息——每轮可变,放用户侧。
- **稳定内容**(persona、场景导航、工具指南)追加到系统提示**尾部**——跨轮逐字节不变,模型厂商的 prompt cache 前缀保持命中。

同一段记忆文本按不可信输入净化后再进注入块:已知包裹标签中和、控制字符剥离、无效代理对替换、字符预算(单条上限 + 总量上限,截断处提示可用 memory_search 查全文)。

## 6. 安全模型

| 面 | 措施 |
|---|---|
| 数据归属 | 全本地 `~/.anta-agent`,无云账户;embedding 可设 none,零额外外发 |
| 注入防御 | 包裹标签中和防逃逸;prompt injection 模式检测;记忆注入块明示"仅供参考,不代表当前任务" |
| 输入边界 | JSONL 回放逐行校验(类型/长度/空字节),畸形行跳过不阻断 |
| 审计 | records/ 追加记录每次写入/更新/合并;场景与人格改动自动备份 |
| 关闭开关 | settings 一项 `memory.enabled: false` 整体停用,数据不动 |

信任边界划分:文件/JSON/LLM 输出是真边界,一律校验净化;进程内类型化调用信任类型,不堆防御代码。

## 7. 可靠性细节

- **优雅关机**:停新工作 → 等待捕获(≤5s)→ flush 管道(≤5s)→ 关 SQLite。等待超时不硬关,延迟到静默后再关——绝不在活跃操作脚下抽走数据库。
- **向量回灌**:embedding 配置变更会清空旧向量,后台批量(32/批)重灌;回灌期间记录若已更新,旧向量丢弃,不复活陈旧文本。
- **插件生命周期**:事件总线在会话重载后失效,日志上报全部吞错——日志永不打断记忆管道。
- **中文统计行**:TUI 底部实时显示输入/输出 token、缓存读写与命中率、美元成本、上下文占比。成本可观测是"省积分"叙事的产品化落点。

## 8. 测试策略

`packages/anta-agent/test/` 五个套件:核心门面、存储层、管道调度、插件集成,以及**对抗性测试**——注入标记逃逸、超长/畸形输入、代理对断裂等恶意场景直接对着安全净化代码打。测试断言外部行为(落库内容、注入文本),不探测内部状态自述。

## 9. 演进口子

`AntaAgent` 门面是宿主中立接缝:当前为本地单进程实现;若接 TencentDB-Agent-Memory 式远程后端(Proxy/知识服务/多租户),在门面之后替换实现即可,本地存储契约与插件层不变。
